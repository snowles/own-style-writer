# Own Style Writer

**让 AI 按你的文风写，并把你改过的问题留给下一次写作。**

把你认可的文章放进一个文件夹，再提供本次素材和写作要求。这个 skill 会让你正在使用的 AI 工具提炼文风、整理素材、出大纲、写正文，并记录改稿反馈。适合持续写公众号、专栏、评论和工作文章的人。

## 比直接让 AI 写，多了什么？

直接对 AI 说“按我的风格写”，你也可以得到一篇文章。Own Style Writer 把参考文章、写作偏好和改稿经验保存成可复用的文件，让后续写作有据可循。

| 你关心的问题 | 这个 skill 的做法 |
| --- | --- |
| 每次都要解释“我的风格是什么” | 从参考文章提炼开头、结构、语气和节奏，保存到 `style.md`，下次先读。 |
| 上次改过的问题，下次又出现 | 把可复用的改稿意见写进 `needtoknow.md`，写前读取，写后逐项检查。 |
| 给了参考文章，AI 连里面的故事也搬过来 | 分开处理“学怎么写”的文章和“这次写什么”的素材，避免把别人的经历写成你的经历。 |
| 文章读着顺，却不知道数字和观点靠不靠谱 | 保留关键材料的来源，区分事实与假设，检查数字、引语和论据，列出未解决的问题。 |

它把这些步骤固定成一套流程，省去你每次重新组织提示词的工作。效果仍取决于所用 AI、参考文章和素材质量；记录偏好也不等于训练模型。

## 怎么用？

将本目录放进 AI 工具支持的 skills 目录，或让支持本地文件的工具读取 [SKILL.md](SKILL.md)。准备两类材料：

- **风格文章**：你自己写过、或你认可其表达方式的文章。
- **本次素材**：这次要用的事实、案例、数据和背景。

然后把下面这段话发给 AI，替换路径和主题即可：

```text
使用 own-style-writer。

参考文风：D:\writing\风格文章
本次素材：D:\writing\本次素材
输出目录：D:\writing\本次输出

帮我写一篇关于【主题】的文章，面向【读者】，约【字数】字。
先给我文风总结和大纲，确认后再写正文。
```

默认先看大纲再写正文；想直接成稿，可以说“跳过大纲确认，直接写”。文件读取、OCR 或转写使用当前 AI 工具已有的能力，不需要额外配置这个 skill 的 API Key。无法读取的文件会列出来，再补充文字版本。

## 改过一次，下次怎么用？

例如你反馈：

> 这篇面向项目经理，开头太绕，直接说问题。把这条记下来，下次写同类文章时注意。

AI 会先改稿，再把“项目管理类文章开头直接点题”写进复盘。下次使用同一套目录写作时，它会先读这条记录，再检查新稿是否重犯。适用范围也会保留，不会因此要求所有文章都用同一种开头。

两份长期记录保存在你的写作目录里，可以查看、修改，也可以交给能读取这些文件的其他 AI 工具继续使用：

```text
写作目录/
├── 风格文章/
│   ├── 你的参考文章……
│   └── style.md          你的文风与表达偏好
├── 写作复盘/
│   └── needtoknow.md     以前的问题与下次避错规则
├── 本次素材/
└── 本次输出/             素材摘要、大纲、正文和检查记录
```

第一次没有改稿反馈时，复盘就是空的。后续积累的是你实际提出的意见。

需要批量整理文件或检查篇幅时，可用随包的可选脚本，详见 [文字整理助手](references/text_preparation.md) 和 [交付检查](references/delivery_checks.md)。日常使用直接与 AI 对话即可。
